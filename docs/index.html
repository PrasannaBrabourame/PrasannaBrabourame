Most AI projects don't fail at the model.

    
They fail in the gap between something that impressed a room and something an officer can defend to a regulator. That gap is where I work.


    
A demo is judged on its best output. A production system is judged on its worst one — the malformed response at 2am, the rate limit during an audit window, the confident answer that was quietly wrong. Everything I build assumes that day has already been scheduled.

    

    

      

        
        
The model is a component, not the architecture

        
Where a decision is safety-critical or legally consequential, it is stamped from the rule book — expiry dates, prohibited terms, severity ratings. The model reads, summarises and proposes. It does not get the final word on anything that has to be defended.

      

      

        
        
Malformed output is a normal Tuesday

        
Models return fenced JSON, truncated arrays, stray control characters. I build layered recovery and deterministic fallbacks so a bad response degrades one row of a report — never the pipeline, never the queue behind it.

      

      

        
        
The system has to heal itself

        
Long jobs die at function timeouts. Gateways rate-limit. Watchdogs sweep for stalled work, resume interrupted phases and mark what cannot be saved, so a human finds a clear error rather than a silent gap.

      

    


    
I trust an LLM exactly as far as its deterministic backstop can throw it.

        National certification authority · Singapore
        Deployed
      

      
Certification document review

      
Certification officers used to read every supporting document page by page. This platform classifies each uploaded file, extracts its structured data, and validates it against the published certification conditions — turning a manual read into a findings-driven review the officer confirms or overrules.

      
      


      

        

          
What I built

          
The React officer console — intake, document workspace, review queue, audit log and PDF report — and the serverless backend behind it: an event-driven pipeline on Cloud Functions integrating two Singapore Government AI services, plus the rules engine encoding the certification conditions.

        

        

          
The hard part

          
Cross-document validation can only run once every document is extracted. A Firestore transaction acts as the barrier so the verification phase fires exactly once per document set — no duplicates, no half-validated applications, whatever order the uploads finish in.

        

        

          
Where the model stops

          
Expired certificates and prohibited terms are caught deterministically, never inferred. Long ingredient and menu lists validate in bounded chunks that bisect down to a single row, so a slow batch degrades gracefully instead of hitting the timeout.

        AML/CFT compliance · Singapore
        Delivered
      

      
Regulatory compliance review

      
Desktop review of regulated firms against a national AML/CFT rule book. Officers open a case, upload the evidence — policies, due-diligence forms, director IDs, screening records — and the platform returns severity-rated findings they can accept, edit or reject, with the edit history kept.

      
      



      

        

          
What I built

          
The solution design and compliance data model, a React 19 review interface, and a Python Cloud Functions analysis engine that runs each rule down two tracks at once — an LLM judgement track and deterministic field validators — before assembling the finding.

        

        

          
The hard part

          
A finding a regulator can act on has to be traceable to a clause. Severity is stamped from the rule book, never inferred by the model, and every finding carries its evidence, its rule reference and its full officer edit history.

        

        

          
Around the edges

          
Deny-by-default Firestore and Storage rules, role-based access across analyst, approver and admin, upload allowlists by MIME and size, admin editors for the rule book and document checklist, and PDF export of the completed review.

        DevSecOps · vulnerability remediation
        Delivered
      

      
Vulnerability remediation pipeline

      
Vulnerability findings arrive from several scanners in several shapes, get de-duplicated and risk-scored, and then travel a full remediation pipeline: ticket, analyse, approve, fix, test, merge. The fix branch is only pushed when the test suite passes.

      
      


      

        

          
What I built

          
A provider-plugin core where source control, issue trackers, notification channels and LLM providers are all swappable adapters — new providers drop in without touching the remediation logic — over a layered Express/TypeScript backend and a Prisma/PostgreSQL model.

        

        

          
The hard part

          
Letting a model write code that reaches a repository. The fix engine works on a dedicated branch, runs the target's own test suite, and pushes only on green; anything else is flagged for a human. An approval gate sits in front, with auto-approve reserved for low-risk policy classes.

        

        

          
Around the edges

          
Cross-source de-duplication and correlation, severity-weighted risk scoring with historical trends, OWASP Top 10 coverage reporting, executive PDF and PowerPoint exports, MTTR metrics, and a token-usage dashboard so the AI spend stays visible.

        Early-childhood education · Singapore
        Delivered
      

      
Early-years learning insight

      
Teachers record what they observe; the observations sit in spreadsheets and never become anything. This platform ingests the tracking sheets, joins them to the canonical curriculum and identity records, and produces per-child readiness insights teachers can actually read.

      
      



      

        

          
What I built

          
Three tiers and the cloud around them: a Go/Gin backend with two-factor sign-in, Excel ingest and a four-strategy name resolver; a Next.js teacher app; and a Python AI tier on Vertex AI Agent Engine running a retrieval → summarisation → evaluation agent sequence.

        

        

          
The hard part

          
Teacher spreadsheets don't spell children's names the way the warehouse does. The name resolver works through four strategies before it gives up, because an unmatched row is a child with no insight — and a silently mismatched one is worse.

        

        

          
Around the edges

          
A two-zone network design, per-IP rate limiting, upload hardening and personal-data redaction in logs — this is children's data. Plus an offline evaluation harness for tuning prompts and cost, and a formal handover package at the end.

How I work

    
Embedded, not delivered from a distance.

    
Forward deployed means what it sounds like: I work inside your constraints, your data rules and your definition of done — not from a statement of work written before anyone had seen the problem.

      
      



    

      

        
I start in your use cases, not my architecture

        
Every platform above began as a set of use cases from the people who do the work. The design followed the constraints they described — the regulation, the review workflow, the thing nobody writes down — rather than the reverse.

      

      

        
I work across the whole stack

        
Interface, AI pipeline, data model, security posture, infrastructure, CI/CD. Fewer seams to negotiate, and nobody waiting on anybody. For a first build in a new domain, that is usually the fastest honest route to something real.

      

      

        
Hardened for the day after go-live

        
Retries with backoff, watchdogs for stalled jobs, layered response recovery, deterministic backstops, audit trails, secrets out of source. The unglamorous half of the work, and the half that decides whether the system is still running in six months.

      

      

        
Built to be handed over

        
Architecture documentation, environment templates, a security and cleanup review, and training material for the people who will use it. The reasoning stays with your team — the next thing they build shouldn't need me.

      

    


    
The best sign a handover worked is that nobody calls.
